# DQH1 M1-EXP: first full skill heading without increasing the menu object

**Prototype, not a validated release.** Japanese Switch version 1.0.0, English text already transplanted from official Western PC. **Only the `Requirements` heading is targeted**. Other truncated skill headings are not changed.

## Why this experiment is different

Disassembly traced the exact **Requirements** source message ID 2942 through the native string lookup at VA `0x21BF58` and into the font renderer at `0x21BFDC`. Its embedded sprite pool is **10 entries of 72 bytes**, but the complete Western PC heading requires **12**. The neighboring **Details** heading (PC message 2945) uses another **10-sprite** pool, but its official English wording has **7 characters**.

We can redistribute their existing **20 sprite slots**, not allocate more memory:

| Field | Before | Proposed after |
| --- | --- | --- |
| Requirements | `this + 0x8D0`, 10 slots, end `0xBA0` | `this + 0x8D0`, **12** slots, end `0xC30` |
| Details | `this + 0xBA0`, 10 slots, end `0xE70` | `this + 0xC30`, **8** slots, end `0xE70` |

Both fields end at the *same original upper boundary*, and other adjacent fields are left untouched. The patch changes exactly three AArch64 instructions. Original Japanese Switch 1.0.0 `main` and official Western PC resources were independently checked. Static tests passed. **Rendering/lifetime reference safety remains subject to Eden validation.** The experiment does **not** establish a general-purpose way to expand the other labels, which use their own packed pools.

## Build in Windows PowerShell

Install the Python module if needed: `python -m pip install lz4`.

If the tested **v9.3.11-EXP** Action List page-switch build is active, use the `exefs/main` generated by that build as the input. This preserves the existing **hold X → second Action List page** functionality:

```powershell
python -X utf8 build_m1_requirements_pilot.py --input-main "C:\PATH\TO\V9311_Test\exefs\main" --output "M1_REQ_TEST\exefs\main"
```

Expected input SHA-256 for that exact v9.3.11-EXP `main`: `39175cf530e8ffd6db162df1ec992706f74b57a7feeb289e09605c16c9c9537e`.

The original, unmodified Japanese Switch v1.0.0 `main` (SHA `cc9dfbc99f1a60120fd30b3e82dc98a17e6b2754f9cad6acfd5be329cbe63e4d`) is accepted too, **but then the v9.3.11-EXP X-button Action List hook is not retained**. All other executable variants are rejected.

The command creates **`M1_REQ_TEST/exefs/main`** and a validation JSON file. It **never overwrites either input** and never edits LINKDATA, saves, opening video, the starting menu or Japanese audio. No copyrighted game files are contained in this ZIP.

## First Eden test

1. Back up the **current working v9.3.11-EXP `exefs/main`**. Install only the newly generated `M1_REQ_TEST/exefs/main` as the ExeFS override in your separate testing profile, while keeping the **same currently working DQH1 gameplay LINKDATA pair**. Do not introduce another overlapping ExeFS mod or change the smaller starting-menu LINKDATA.
2. Verify the game boots past the 30th Anniversary splash and that gameplay loads; **do not save during this initial test**.
3. Open **Allocate Skill Points** → the skill tree where Doric's **Requirements** heading previously displayed `Requiremen`. Confirm whether it now displays **Requirements** in full.
4. Select a skill and verify the **Details** heading is still complete and displays normally. Change characters and skill choices; check there is no overlapping art or missing text. **Points Required**, Attributes, and other clipped headings are deliberately unchanged.
5. Open the Action List, hold **X** to confirm that v9.3.11 pagination still works if you built on that executable. Release X to return to page 1. Back out of the menus without saving.
6. If anything fails, **restore the backed-up previous `exefs/main`**. No gameplay archive restoration is needed because this test does not modify LINKDATA.

**Please report whether Requirements and Details both display in full.** A screenshot is useful. Do not treat this as a stable M1 solution until observed in Eden.

## Static verification

- Original 1.0.0 NSO original SHA-256 checked, or known v9.3.11-EXP executable exact SHA checked.
- Three precise native instruction sites verified and changed, then disassembled back into `Details pool +0xC30`, `Details count 8`, and `Requirements count 12`.
- NSO text sections recompressed and round-trip checked. All rodata/data decompressed content unchanged.
- Pagehook instruction and its 132-byte code kept byte-for-byte identical when the pagehook input is used.
- Five source-only tests passed with local user-supplied input NSOs. Every failure to match the expected code fails closed.

The separate read-only audit `audit_six_skill_labels.py` confirms direct call paths for **Requirements, Points Required, Attributes, Spells and Abilities, Skill Points, Switch Character**, and identifies distinct sprite pools. Its report is informational, not a universal patch.

## Eden validation received: 2026-10-13

**Successful focused pilot.** User's screenshot shows full **Requirements** and full **Details**. User explicitly confirms X-held Action List pagination still works on the combined executable. The sprite capacity was rebalanced within the same 20-slot object region without visible collision in the tested screenshot. This validates the targeted patch in Eden only; expanded character switching, saves/loads, and comprehensive regression testing are not yet documented. **Keep marked EXP; do not declare production-stable.**
